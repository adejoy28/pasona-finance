**PROMPT:**

Build a personal finance tracker web app using **Laravel (API backend)** and **Next.js (frontend)** with **PostgreSQL** as the database. The app must be a **Progressive Web App (PWA)** — mobile-first, installable on Android, works offline, syncs when back online. It will also work on desktop. Hosted on **cPanel**. Use **Google CLI** for deployment. Write all code with **detailed comments** so a junior developer can read and understand every line.

---

**CORE FEATURES:**

1. **Quick Transaction Entry** — Minimal taps: Amount → Category → Account → Save. No unnecessary fields required upfront.

2. **Account Management** — Multiple accounts (Bank, Mobile Money, Cash). Each account shows live balance = Starting Balance + Total In − Total Out.

3. **Transaction Types:**
   - Income: money coming in to an account
   - Expense: money going out from an account
   - Transfer: money moving between own accounts — does NOT count as income or expense

4. **Categories** — Predefined list (Food & Groceries, Transport, Healthcare, Bank Charges, Shopping, Entertainment, Utilities, Rent, Airtime & Data, Education, Savings, Tithe, Salary, Freelance, etc). User can add custom categories.

5. **Offline First** — All transactions logged locally when offline. Auto-syncs to PostgreSQL via Laravel API when internet is restored. Use service workers and IndexedDB for offline storage.

6. **Bank Statement Import** — User can paste or upload a CSV bank statement. App parses it, checks for duplicates (by date + amount), and shows which rows are new before importing.

7. **Dashboard** — Shows: current balance per account, total income vs expenses this month, spending breakdown by category (simple text list, no charts needed for now).

8. **Daily Reminder** — PWA push notification at a user-defined time (default 9:10 PM) reminding user to log expenses.

9. **Duplicate Detection** — Flag transactions with same date + type + amount as potential duplicates before saving.

**TECHNICAL REQUIREMENTS:**

**Backend (Laravel):**

- RESTful API only (no Blade views)
- PostgreSQL database
- Migrations for: users, accounts, transactions, categories
- API routes: CRUD for accounts, transactions, categories; import endpoint; monthly summary endpoint; category breakdown endpoint
- Sanctum for API authentication
- Queue jobs for sync processing
- Every function, class, and migration must have clear comments explaining what it does and why

**Frontend (Next.js):**

- Mobile-first responsive layout
- PWA setup: manifest.json, service worker, offline fallback page
- IndexedDB for offline transaction queue
- Auto-sync hook: when navigator.onLine becomes true, flush offline queue to API
- Pages: Login, Dashboard, Add Transaction, Transactions List, Accounts, Import, Settings
- No UI library required — plain clean HTML/CSS or Tailwind only
- Every component and function must have comments explaining props, purpose, and logic

**Database Schema (PostgreSQL):**

- `users` — id, name, email, password, reminder_time, timestamps
- `accounts` — id, user_id, name, type (bank/mobile/cash), starting_balance, notes, timestamps
- `categories` — id, user_id, name, type (income/expense), is_default, timestamps
- `transactions` — id, user_id, account_id, to_account_id (nullable, for transfers), type (income/expense/transfer), category_id, amount, description, reference, transaction_date, is_synced, timestamps

**Deployment (cPanel + Google CLI):**

- Laravel API deployed to subdomain (e.g. api.yourdomain.com) on cPanel
- Next.js exported as static PWA or Node deployment on cPanel
- Environment variables via .env
- Include deployment instructions as comments in a DEPLOY.md file
